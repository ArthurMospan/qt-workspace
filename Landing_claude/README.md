# Лендінг QuickTeam

Окремий статичний сайт. Він **не є частиною застосунку**: нічого не імпортує
з `src/`, не збирається разом з ним і не впливає на UI Kit. Кольори, радіуси
й розміри контролів переписані сюди вручну з `src/app/globals.css` та
`src/components/ui/Button.jsx` — щоб цю теку можна було винести в інший
репозиторій одним рухом.

## Як відкрити

Подвійний клік по `index.html`. Збірки немає, залежностей немає.

Якщо потрібен локальний сервер (наприклад, щоб перевірити відносні шляхи так,
як їх побачить хостинг):

```bash
npx serve Landing_claude
```

## Що всередині

| Файл | Що тримає |
| --- | --- |
| `index.html` | Уся розмітка сторінки, включно з мокапами інтерфейсу |
| `assets/landing.css` | Токени, каркас, кнопки, шапка, герой і мокапи продукту |
| `assets/sections.css` | Секції сторінки, підвал, поява при скролі, вузькі екрани |
| `assets/landing.js` | Уся поведінка: масштаб мокапів, поява, сцена на дошці, питання |
| `assets/mark.svg` | Знак QuickTeam (копія `public/logo-min.svg`) |
| `tools/` | Скрипти для зйомки справжніх екранів і перевірки сторінки |

Сторінка читається без JavaScript: скрипт додає рух, а не вміст.

## Кольори

Сторінка темна — це колір сайдбару продукту (`#1f1f1f`), винесений на всю
поверхню. Ролі перевернуті: у застосунку `#1f1f1f` — це текст на світлому
полотні, тут це поверхня, а полотно `#f4f4f5` стало текстом.

Акценти — `#cf7a22` і `#0e8f74` — узяті з палітри графіків продукту
(`--color-chart-2` і `--color-chart-3`). Третього акценту немає навмисно.

Кнопки повторюють геометрію `Button.jsx` (36/32px, радіус 10px, поля 18px,
текст 13px) і міняють лише колір. **У самому UI Kit нічого міняти не треба** —
ці правила живуть тільки тут.

## Шрифти

Ті самі дві гарнітури, що в продукті: **Roboto Condensed** на заголовки
й **Inter** на текст. Числа, індекси й підписи даних — системний моноширинний.

## Знімки продукту

Зараз великі блоки показують мокапи інтерфейсу, зверстані розміткою: вони
різкі на будь-якій щільності пікселів і не старіють разом зі скріншотом.
Місця, куди підуть справжні знімки, позначені в `index.html` коментарями
`<!-- SHOT: ... -->`.

Щоб зняти справжні екрани:

```bash
node Landing_claude/tools/capture.mjs --probe          # відкрити й залогінитись
node Landing_claude/tools/capture.mjs --shots          # зняти повний набір
node Landing_claude/tools/capture.mjs --shots --only=board,analytics
```

Скрипт відкриває окреме вікно Chrome із власним профілем у `tools/.profile`
(не чіпає ваш основний браузер), чекає на вхід, знаходить перший проєкт
і зберігає PNG у `assets/shots/`. Вхід треба зробити руками один раз —
далі сесія переживає перезапуски.

Знімати варто **демо-організацію**, а не робочий простір: сторінка публічна,
і на ній не місце справжнім назвам клієнтів, сумам і прізвищам.

## Перевірка

```bash
node Landing_claude/tools/check.mjs 1440   # числа: переповнення, шкали, лічильники
node Landing_claude/tools/check.mjs 390    # те саме на ширині телефона
```

`tools/preview.mjs` знімає сторінку в кількох позиціях скролу, якщо треба
подивитись очима:

```bash
MARKS='[["top",0],["board",620]]' node Landing_claude/tools/preview.mjs ./out 1440
```

Обидва скрипти беруть Playwright з `node_modules` кореневого проєкту — це
єдине, чим лендінг до нього дотикається, і тільки в інструментах розробки.
Сама сторінка не залежить ні від чого.

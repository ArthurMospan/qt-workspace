## 1. Навіщо цей зріз

Фаза 4a завершилась із зеленими 53 тестами, чистим lint, успішним білдом і схваленим фінальним рев'ю — і **непрацездатним екраном**. Користувач відкрив preview-деплой гілки й сказав: «наче все бачу, щоправда поки це безполезно бо ні перегляду немає, ні скачати не виходить, виглядає ця сторінка жахливо, ні ux ні ui».

### 1.1. Кореневий дефект: читаємо неіснуюче поле

`src/lib/portal/qtplusMaterialView.mjs` робить:

```js
const href = raw.url || null;
```

Реальна схема матеріалу в порталі (джерело: `qt/src/components/MaterialsGrid.jsx`, `qt/src/lib/hooks/useMaterials.js`):

| Поле | Для чого | Хто використовує |
|---|---|---|
| `previewUrl` | URL файлу на Cloudinary | file, image, video, PDF, документи |
| `audioUrl` | URL аудіофайлу | audio |
| `url` | URL зовнішнього посилання | **тільки `type: 'link'`** |

Портал скрізь резолвить так:

```js
const url = m.previewUrl || m.audioUrl || m.url;              // download
const audioSource = material.audioUrl || material.previewUrl || material.url;  // audio
```

Отже для `type: 'file' | 'image' | 'audio'` наше `href === undefined` → картка рендериться **без посилання**. Не «превʼю поганеньке» — клікати нема на що, скачати нема що. Це рівно те, що бачив користувач.

### 1.2. Чому 53 тести це пропустили

`tests/qtplus-material-view.test.mjs` перевіряє `toMaterialView` проти **вигаданих** фікстур, у яких `url` присутній у кожному матеріалі. Схему брали з голови, а не з репозиторію `qt`. Тести перевіряли, що код робить те, що написано, а не те, що потрібно. Код мертвий, тести зелені, рев'ю схвалило.

**Урок, який ця спека закріплює:** фікстури для порталу мусять походити з реальних доків / реального коду порталу, і це вимога до тестів у §8.

### 1.3. Друга проблема: екран порожній і незручний

Навіть із виправленим полем поточний вигляд — вертикальний акордеон, у якому матеріали затиснуті в одну вузьку колонку. Превʼю 160px там виглядають погано, багато матеріалів = довга кишка.

## 2. Цілі та не-цілі

### Цілі
1. Матеріали резолвлять URL так само, як портал — файли відкриваються й скачуються.
2. Повний паритет превʼю з порталом: зображення, PDF, відео, аудіо, код/текст, Office, OG-картки лінків.
3. Компонування «степер + сітка» замість акордеона.
4. Етапи `todo` заблоковані (паритет із порталом).
5. Керування привʼязкою (Фаза 3) стискається в один рядок із меню.
6. Тести проти реальної схеми порталу.

### Не-цілі (свідомо поза зрізом)
- **Будь-який запис у портал.** Чеклист і опитування — read-only. Тицяння в чекбокс, голосування, затвердження етапу, надсилання — це наступний зріз («інтерактив») за роадмапом користувача.
- Чат проєкту — Фаза 4b, окремо.
- Зміна `firestore.rules` у будь-якому репозиторії.
- Зміни в репозиторії `qt`.

## 3. Схема даних (джерело істини — репозиторій `qt`)

### 3.1. Етап — `stages/{stageId}`
```
projectId: string
label:     string
status:    'todo' | 'in-progress' | 'done'
order:     number
```
Запит: `where('projectId','==',id)`, `orderBy('order','asc')` — уже реалізовано в `usePortalStages`, не змінюємо.

### 3.2. Матеріал — `stages/{stageId}/materials/{id}`
```
type:        'file' | 'image' | 'audio' | 'link' | 'checklist' | 'poll' | 'note'
title:       string        // містить розширення: 'logo-v2.png'
desc:        string?
order:       number
previewUrl:  string?       // Cloudinary — файли/зображення/відео/PDF/документи
audioUrl:    string?       // Cloudinary — аудіо
url:         string?       // ТІЛЬКИ для type='link'
fileType:    string?       // MIME
storagePath: string?       // Cloudinary publicId
duration:    string?       // аудіо, '01:24'
items:       string[]?     // checklist
checkedItems: number[]?    // checklist — індекси
options:     string[]?     // poll
votes:       number[]?     // poll
votedBy:     string[]?     // poll
content:     string?       // note
color:       string?       // note
source:      string?       // note
ogImage/ogTitle/ogDescription: string?  // link
```
Запит: `orderBy('order','asc')` — уже реалізовано в `usePortalStageMaterials`, не змінюємо.

**Важливо:** файли лежать на **Cloudinary**, не у Firebase Storage. URL-и не потребують авторизації — хто має URL, той має файл.

### 3.3. Тип визначається розширенням із `title`, не лише полем `type`

Портал так робить (`MaterialsGrid.jsx`): `type: 'file'` із `title: 'promo.mp4'` рендериться як відео. Тому наш view-model мусить розбирати розширення, а не довіряти лише `type`.

## 5. Компонування

### 5.1. Рядок привʼязки (варіант A, обрано)
Один рядок ~28px: `🔌 Привʼязано до «Ребрендинг Acme»` + меню `⋯` → «Змінити привʼязку» / «Відвʼязати». Учасник (не owner/admin) бачить рядок без меню. Непривʼязаний стан для owner/admin — поточний пікер Фази 3 без змін (це єдиний контент вкладки, місця вистачає).

### 5.2. Степер
Горизонтальний, скролиться, активний етап підкреслено. Кожен елемент: кольорова крапка статусу + назва + `🔒` для `todo`. Автоскрол до активного.

Вибір активного етапу за замовчуванням, у порядку:
1. перший `in-progress`;
2. інакше — **останній** `done` (найсвіжіше завершене, що є що показати);
3. інакше — жодного (усі етапи `todo`).

Випадок 3 реальний: новий проєкт, роботу ще не почато. Тоді степер рендериться повністю заблокованим, жоден крок не активний, а замість сітки показуємо «Роботу над проєктом ще не розпочато.» Без цієї гілки екран був би степером із самих замків і мовчазною порожнечею.

### 5.3. Замки (паритет із порталом)
`canAccess(stage) = stage.status === 'done' || stage.status === 'in-progress'`.
Клік по заблокованому — no-op, курсор `not-allowed`, тултип «Етап ще не розпочато».

**Це UI-правило, не безпека.** Firestore віддасть матеріали `todo`-етапу будь-якому члену команди. Замок відтворює поведінку порталу, щоб два продукти поводились однаково. Ніякої безпекової ваги він не несе, і спека це фіксує явно, щоб наступний читач не вирішив, що на нього можна покластися.

### 5.4. Сітка
`grid`, 1 колонка < 640px, 2 до 1024px, 3 далі. Проміжок 12px.

### 5.5. Заголовок сітки
`<Назва етапу>` + `N матеріалів · прогрес X% (done/total)`.

## 6. Картки й превʼю

Загальне: рамка `border-line`, фон `bg-surface`, радіус 12px. Бейдж типу в лівому верхньому куті мініатюри. Кнопка `⤓` у правому верхньому куті на ховері (і завжди на тач-пристроях — ховера там немає).

| Тип | Мініатюра | Клік | Скачати |
|---|---|---|---|
| image | `<img src={url}>`, 160px, object-cover | лайтбокс | так |
| pdf | `PdfThumb` (pdf.js, 1-ша сторінка) | лайтбокс (iframe) | так |
| video | `<video>` inline, play/pause/seek | лайтбокс | так |
| audio | без мініатюри; плеєр у картці | — | так |
| код/текст | `TextThumb` (перші 500 байт, `<pre>`) | лайтбокс | так |
| office | `OfficeThumb` (iframe Microsoft) | нова вкладка | так |
| інші файли | іконка + бейдж розширення | нова вкладка | так |
| link | OG-картка (`ogImage`/`ogTitle`) або іконка | нова вкладка | ні |
| note | текст, `whitespace-pre-wrap`, обрізання + градієнт | лайтбокс | ні |
| checklist | read-only, прогрес-бар, `line-through` | — | ні |
| poll | read-only, бари з % | — | ні |

### 6.1. Скачування — `downloadMaterial.js`
Патерн порталу (`MaterialsGrid.jsx:1120`):
```js
fetch(url) → blob → URL.createObjectURL → <a download={title}> → click → revoke
catch → toast('Відкриваємо у новій вкладці') → window.open(url, '_blank')
```
Фолбек критичний: Cloudinary може не віддати CORS-заголовки для деяких типів, тоді `fetch` падає — і користувач усе одно отримує файл.

### 6.2. OG-превʼю лінків — тільки читання
Портал, не знайшовши `ogImage`, фетчить `/api/link-preview` **і записує результат назад у матеріал**. Ми цього **не робимо** — це запис у портал. Показуємо `ogImage`/`ogTitle`, якщо портал їх уже зберіг; інакше — іконка + домен + favicon. Деградація, а не запис.

### 6.3. pdf.js — з npm, не з CDN
Портал інжектить `<script>` з `cdnjs.cloudflare.com` у рантаймі. Ми ставимо `pdfjs-dist` як залежність. Причина не безпекова (PDF рендериться локально, файл нікуди не їде), а інженерна: зовнішній CDN — стороння точка відмови й зайва латентність. Вигляд ідентичний.

### 6.4. Office-превʼю — усвідомлений компроміс
`OfficeThumb` віддає URL файлу в `https://view.officeapps.live.com/op/embed.aspx?src=...`, тобто **URL клієнтського документа їде на сервери Microsoft**, і Microsoft його завантажує. Cloudinary-URL-и не авторизовані — хто має URL, той має файл.

Ризик проговорено з користувачем, рішення: **залишити**, бо портал уже робить рівно це з тими самими файлами, і паритет важливіший. Спека фіксує це як свідомий вибір, а не недогляд.

## 8. Тестування

### 8.1. Автотести (`node --test`) — чисті хелпери
`tests/qtplus-material-view.test.mjs` **переписати**. Вимога: **фікстури беруться з реальної схеми порталу** (§3.2), а не вигадуються. Кожна фікстура супроводжується коментарем із посиланням на місце в `qt`, звідки взято форму доку.

Покриття:
- `resolveMaterialUrl`: file→`previewUrl`; audio→`audioUrl`; audio без `audioUrl`→`previewUrl`; link→`url`; порядок пріоритетів; усе відсутнє→`null`.
- **Регресійний тест на кореневий дефект:** `{type:'file', previewUrl:'https://…/a.pdf'}` → `url !== null`. Цей тест падає на поточному коді.
- `kindOf`: розширення перемагає (`{type:'file', title:'promo.mp4'}` → `video`); `heic`→image; невідоме→`file`.
- `badgeFor`: `.docx`→`DOCX`; без розширення→`FILE`.
- `stageProgress`, `stageStatusMeta` — без змін.
- `canAccessStage`: `todo`→false, решта→true.
- `defaultStageId` (§5.2): є `in-progress`→він; лише `done`→останній `done`; усі `todo`→`null`; порожній масив→`null`.
- `resolveMaterialUrl` відкидає не-http(s): `javascript:alert(1)`→`null`, `data:…`→`null`.

### 8.2. Не автотестуємо
Картки, лайтбокс, плеєр, степер — `eslint` + `npm run build` + браузерний E2E користувачем. Мокати `<audio>`/`<video>`/pdf.js під node — тест, який перевіряє мок, а не продукт. Саме такий тест і пропустив кореневий дефект.

### 8.3. Гейт read-only
Перед PR: `grep -rE "addDoc|updateDoc|deleteDoc|setDoc|deleteField|writeBatch" src/lib/portal src/components/workspace/qtplus` → має бути порожньо (виняток: `qtplusProjectLink.js` Фази 3 пише у **воркспейсну** БД, не в портал).

### 8.4. Браузерний E2E (робить користувач)
Відкрити привʼязаний проєкт → вкладка QuickTeam+ → степер із замками → клік по етапу → сітка → зображення відкривається в лайтбоксі → PDF показує мініатюру → аудіо грає й перемотується → `⤓` качає файл із правильним імʼям → зміна в порталі зʼявляється наживо.

## 10. Успіх

1. Файл, зображення, PDF, відео, аудіо, документ — **відкриваються й качаються**.
2. Зображення/PDF/відео/код мають мініатюру; аудіо має плеєр.
3. Степер із замками, сітка на всю ширину.
4. Рядок привʼязки не займає більше одного рядка.
5. У портал не записано **нічого**.
6. `node --test` (з регресійним тестом), `npm run lint`, `npm run build` — зелені.
7. Користувач проходить E2E з §8.4 і каже, що це більше не «жахливо».

## 11. Відкладені follow-up'и Фази 4a

Забираємо в цей зріз (вони тепер по дорозі):
- Валідація схеми `href` (`javascript:` URL) — `resolveMaterialUrl` пропускає лише `http:`/`https:`.
- `aria-expanded` — неактуально, акордеон зникає; натомість `aria-current` на активному кроці степера й `aria-disabled` на заблокованих.
- `.kind`/`id` у тестах — покривається переписаними тестами.

Лишається на потім:
- Пропуск приреченого `listen` при `staleAccess`.
- `usePortalSession` без `onAuthStateChanged`.
